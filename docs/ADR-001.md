# ADR 001 — Codex transport, conversation ownership and account boundaries

Discovery date: 2026-10-20. Installed binary: `codex-cli 0.163.0`.
Evidence: retained CLI help, generated schemas under `docs/protocol/schema`, official
https://developers.openai.com/codex/app-server (reference summary retained), and the
upstream rust-v0.163.0 app-server README. Generated schemas are authoritative for
this installation; online documents can describe newer releases.

| Capability | Evidence / decision |
|---|---|
| stdio JSON-RPC | Official protocol; use private child processes and newline-delimited JSON. |
| WebSocket | `app-server --listen ws://IP:PORT`, authentication flags in help; official docs call transport experimental/unsupported. Not the default. |
| Remote TUI | `codex --remote`, `codex resume --remote ADDR THREAD_ID` exposed in help. Native clients can bypass bridge ownership. Not used by managed sessions. |
| Shared threads | Thread resume/read APIs and remote TUI exist. Native `codex resume THREAD_ID` with the same CODEX_HOME was verified to open an app-server-held thread READ-ONLY ("opened elsewhere"), making parallel viewing safe under that protection. Use the bridge terminal for approvals and ownership control. |
| Persistent history | `thread/start` with `ephemeral:false`, `thread/resume`, `thread/read`; paginated item/turn APIs. Persist thread ID; never resend prompts on recovery. |
| Steering | `turn/steer`, requires `expectedTurnId`. Expose explicit steer; ordinary send rejects busy threads. |
| Approvals | Server requests `item/commandExecution/requestApproval`, `item/fileChange/requestApproval`; respond using original JSON-RPC ID. No automatic approvals. Other requests fail closed, with an event. |
| Account selection | CODEX_HOME isolates Codex configuration, credentials and local histories. CLI profile is configuration, not identity selection. One fixed CODEX_HOME per process. |
| Cross-account history | No supported cross-home migration verified. Try same thread ID only explicitly at idle boundary, rollback on unavailable history. Offer explicit new-session handoff with user-written summary; never copy credential/history databases. |

One child process per bridge session reduces failure scope and approval ambiguity.
SQLite stores jobs, thread registry, redacted events, approvals and webhook outbox.
All mutations lock per session. Separate bearer credentials identify Grok/human;
control ownership is enforced server-side. Daemon is single-worker with a file lock.
Turn requests are committed as dispatching before RPC. Ambiguous dispatches become
uncertain/interrupted; they are not automatically retried. History and execution
are separate: resuming loads history and does not restart interrupted work.

Default: workspace-write, on-request, human approval reviewer; repository roots
are canonicalized and allowlisted. No public App Server listener. tmux is a view
of the bridge API, never an event source. Webhooks contain metadata/counts only,
not source, command output, prompts, model responses or credential payloads.

## Live probes

An isolated, unauthenticated CODEX_HOME successfully completed initialize,
thread/start and metadata-only thread/read. This installation defaults to
paginated history. `thread/read(includeTurns:true)` and default thread/resume
returned `-32601: list_turns is not supported yet`; `thread/items/list` returned
`-32601: thread/items/list is not supported yet`. Empty threads cannot resume
before their first user message (`no rollout found` / `not materialized yet`).
Use `excludeTurns:true` on resume. The bridge terminal hydrates its own retained
redacted event history; it does not claim full Codex-native history hydration.
Model execution, live steering and real approval issuance require an authorized
account and are separated from protocol and mock-based verification.


The one-command demo has a narrowly scoped client recovery: after verified local
login, it may retry one definitively failed authentication turn whose complete
structured history shows no tool execution. It retains the same thread, reloads
credentials by stop/resume, and journals phase request IDs before dispatch. This
does not permit replay of uncertain/interrupted execution or tool side effects.
