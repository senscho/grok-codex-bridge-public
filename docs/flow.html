01 / MAP

Two directions. One controlled boundary.

The bot sends work inward; metadata flows outward. Each bridge session gets its own Codex app-server process and persistent thread. The human controls approvals through the local API.
02 / SEQUENCE

A task, an approval, a handback.

Follow-ups reuse the session with codex_send. Keep the same idempotency key when retrying a lost response. An approval can be accepted only with local human credentials.
03 / TRUST

Each credential has one job.

BOT → BRIDGE

Grok bearer token

Lives in the bot's secret store. Authorizes work and logs in allowed repositories. Can decline or cancel approvals; cannot accept them.

BRIDGE_GROK_TOKEN
HUMAN → BRIDGE

Human bearer token

Stays on the Mac. Never give it to a bot. Accepts approvals and controls ownership/account registration through local tools.

BRIDGE → RECEIVER

Webhook credentials

The receiver's Authorization header targets one routine. A separate HMAC secret signs metadata. Deduplicate IDs and check freshness.

BRIDGE_WEBHOOK_AUTH_HEADER
BRIDGE_WEBHOOK_SECRET
The URL selects the bot. Set BRIDGE_WEBHOOK_URL and its auth header to the routine of the bot that owns Codex work. Only that bot wakes. Other bots hear through its relay. Alert for approval pending, login expired or process disconnected; send a short finished/failed-turn wrap-up.

Loopback binding, HTTPS transport, canonical repository allowlists and per-account CODEX_HOME boundaries work together. Defaults are workspace-write, on-request, human reviewer. Keep all config, state and captures private; redaction is best effort.

04 / CONTINUITY

History survives. Instructions are not replayed.

  1. Create
    Register an account, start a session in an allowed repo and save the returned session/thread/job IDs.
  2. Work and observe
    Turns move between running, approval and idle. Poll events; use explicit steering for an active turn.
  3. Take over and hand back
    /takeover gives the human ownership. /grok returns it. Detaching the terminal is separate.
  4. Stop or resume
    Stopping preserves history. Resuming loads the same thread, without resending its prompt.

When the bridge restarts

Idle, materialized sessions come back. An in-flight turn becomes interrupted or uncertain, and is never automatically replayed. Inspect files and job state before issuing more work.

Old approval RPCs become stale after process loss. A recorded live process can block recovery until a human inspects it.

When notifications get old

Startup and redelivery expire events older than BRIDGE_WEBHOOK_MAX_EVENT_AGE_SEC, default 900 seconds. Local history stays available. After an outage, poll status for unresolved approvals that outlived their alert.

05 / VISIBILITY

Watch the same conversation.

Native Codex view

Use the registered account's same CODEX_HOME and thread ID from bridge status:

CODEX_HOME=/path/to/account \
  codex resume THREAD_ID

Verified: Codex's built-in protection opens a thread held by the bridge's app-server as READ-ONLY (“opened elsewhere”). Parallel viewing is safe under this protection. Keep approval/control in bridge attach.

tmux live view

Set a large limit in ~/.tmux.conf before creating the window:

set-option -g history-limit 100000

Resize to the viewer's columns and rows (replace C/R with numbers). tmux renders at its own size.

tmux resize-window -t TARGET -x C -y R
tmux capture-pane -t TARGET \
  -p -e -J -S - -E -

ANSI colors, joined wraps, all retained scrollback. Use the session from grok-codex attach SESSION_ID as TARGET. Captures are private logs.

06 / BACKUP + OPTIONS

Catch missed events. Choose review deliberately.

Webhooks can fail, expire or be dropped. The scheduled backup polls sessions independently; it does not change which ONE bot receives the webhook.

Quiet recovery of missed reports

Install both alert and watchdog routine templates on the owning bot. The watchdog checks every 10 minutes for pending approvals over 5 minutes, unreported finished turns, active sessions silent over 20 minutes and errors. Shared cursors and incident/job IDs suppress duplicate reports. No new condition means no message.

Ignore progress-only or stale webhook bodies (over 15 minutes); current unresolved conditions are still visible to the watchdog. Both routines observe and report only.

Normal by default. YOLO by choice.

The delegate skill asks before session creation. Bot acceptance requires explicit session-specific chat consent, and the current connector still has no accept tool. The owner can instead run the local helper:

bash scripts/auto-approve.sh SESSION_ID --enable-yolo

This weakens human review. It accepts inspectable command/file approvals for that session, holding denied or incomplete requests for the human. Deny rules are heuristics, not a security boundary. It stops at idle, on Ctrl-C or on API error. Keep the human token on the Mac. Read the risks.
